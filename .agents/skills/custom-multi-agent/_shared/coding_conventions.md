# 프로젝트 코딩 컨벤션 (Coding Conventions)

> 이 문서는 워커가 코드 작성 시 참고하는 실용적 품질 기준입니다.
> 비평 워커는 이 기준을 기계적 강제가 아닌 실질적 결함 및 복잡성 억제 관점에서 검증합니다.

## 1. 인터페이스 및 책임 분리
* 도메인 경계가 나뉘거나 책임이 명확히 다를 때 인터페이스를 적절히 분리한다 (단, 작은 수정이나 단순 연관 기능에 무리한 단일 메서드 인터페이스 분리를 강제하지 않는다).
* 기존 코드베이스의 아키텍처 패턴(포트-어댑터, 서비스 계층 등)과 계층 구조를 존중한다.

## 2. 초기화 및 방어적 코딩
* 필드 초기화는 가급적 생성자나 초기화 단계에서 명확히 수행한다.
* 메서드 진입 시 매개변수 유효성 검사 및 가드문(Guard clause)을 권장하되, 자연스러운 흐름을 해치지 않는 단순 조건문은 허용한다.

## 3. 실용적 중복 제거
* 실질적인 비즈니스 로직이나 복잡한 알고리즘이 2곳 이상에서 중복될 때 공통 헬퍼로 추출한다.
* 2~3줄 수준의 단순 호출, 가독성을 위한 의도적 인라인 로직까지 무조건 함수로 쪼개어 파일 복잡도를 높이지 않는다.
* 리소스/데이터 접근(쿼리, API 호출 등)의 핵심 패턴은 일관성을 유지한다.

## 4. 단순성과 기존 스타일 보존
* 기존 소스 코드의 서식, 명명 규칙, 주석 스타일을 최대한 보존한다.
* 과도한 추상화, 불필요한 제네릭/리플렉션, 복잡한 람다 중첩을 지양하고 직관적이고 표준적인(Idiomatic) 코드를 작성한다.
* 성능 핫스팟(대량 반복문, 빈번한 렌더/이벤트 루프)에서는 불필요한 객체 할당(GC 압박)을 피한다.

## 5. 네이밍
* 클래스 및 함수명은 그 책임과 동작을 직관적으로 드러내도록 작성한다.
* 불필요하거나 자의적인 약어를 지양하고 프로젝트 내 통일된 용어(또는 CONTEXT.md)를 사용한다.
